# TrackNet: A Deep Learning Network for Tracking High-speed and Tiny Objects in Sports Applications

- 저자: Yu-Chuan Huang, I-No Liao, Ching-Hsuan Chen, Tsì-Uí İk, Wen-Chih Peng
- 발표: AVSS 2019
- 논문: https://arxiv.org/abs/1907.03698
- 코드: 공식 V1 코드 확인 안 됨

## 한 줄 요약
스포츠 중계 영상에서 작고 빠르게 움직이는 공을 추적하기 어려운 문제를 해결하기 위해, 연속된 프레임을 입력받아 공의 위치를 히트맵(Heatmap)으로 예측하는 방법을 제안한다.

## 해결하려는 문제

- **배경:** 공의 궤적 데이터는 선수 평가와 경기 전략 분석에 중요한 기초 정보다.
- **문제:** 공은 크기가 작고 이동 속도가 매우 빨라 영상에서 흐릿하게 촬영되거나 정확한 위치를 파악하기 어렵다.
- **대상 영상:**
    - 주요 대상은 테니스 중계 영상이다. 공이 작고 흐리며, 잔상(afterimage)이 남거나 아예 보이지 않는 경우도 있다.
    - 확장 실험으로 배드민턴도 다룬다.
    - 방송 영상뿐 아니라 스마트폰 같은 일반 기기로 찍은 영상도 대상으로 말한다.
- **기존 방법의 한계:**
    - 상용 시스템(Hawk-Eye 등)은 고해상도·고프레임 영상, 전문 카메라 및 운영 인력이 필요해 구축 및 운영 비용이 높다.
    - 작은 공이 색상이나 형태가 비슷한 물체와 혼동되어 오검출(False Positive)이 발생할 수 있다.
    - 공의 빠른 움직임으로 모션 블러가 발생해 공을 탐지하지 못하는 미검출(False Negative)가 발생할 수 있다.
    - 형태, 색상, 크기 또는 HOG, SIFT 등의 외형 특징에 의존하는 방법은 모션 블러와 잔상이 발생하면 인식 정확도가 떨어진다.
    - 기존 궤적 기반 방법은 프레임별로 찾은 공 후보를 궤적 모델이나 파티클 필터 등 규칙 기반 기법으로 연결한다. 논문은 이를 대체해 궤적 패턴을 학습하는 방식을 제안한다. 
- **이 논문의 목표:** 단일 프레임의 공 이미지 인식뿐 아니라, 연속 프레임에서 공의 궤적 패턴까지 딥러닝으로 학습해 공의 위치를 정확하게 추정한다.
- **가정:** 코트에 공은 최대 1개라고 가정한다.

## 문제 정의

- **Input:** 연속된 프레임. 입력 프레임 수는 네트워크 설정값이며, 논문에서는 1장 모델(Model I)과 연속 3장 모델(Model II)을 구현해 비교했다. (4장)
    - 원본 1280x720 프레임을 640x360으로 리사이즈해 사용한다. (5장)
    - 3장 모델은 연속된 3프레임을 입력받아 마지막 프레임의 공 좌표를 예측한다. (5장)

- **Output:** 입력 프레임과 같은 해상도의 히트맵 1장 (4장)
    - **정답 히트맵:** 공 중심에 2D 가우시안 분포를 배치한다. 분산은 σ²=10이며, 값의 범위는 0~255다. (4장)
    - **모델 출력:** 각 픽셀은 0~255 범위의 grayscale 값을 가진다. (4장)
    - 모델은 히트맵을 출력하며, 공 좌표는 별도의 후처리로 계산한다.
    - 네트워크의 마지막 층은 픽셀마다 256단계(0~255)의 확률을 내고, 그중 가장 높은 값을 고른 것이 히트맵이 된다. (4장, 표 II)

- **Task:** 각 프레임에서 공의 (x,y) 좌표를 추정한다.
    - **후처리 (4장)**
        1. 히트맵을 임계값 128로 이진화한다. (128 이상이면 255, 미만이면 0)
        2. 이진 히트맵에 Hough Gradient Method를 적용해 원을 찾는다.
        3. 원이 정확히 1개 발견되면 원의 중심을 공 위치로 반환한다. 그 외에는 공이 검출되지 않은 것으로 처리한다.

- **Assumption / Limitation:**
    - 코트에 공은 최대 1개라고 가정한다. (서론)
    - 원이 정확히 1개가 아니면(0개이거나 2개 이상) 검출 실패로 처리한다. (4장)
    - 임계값 128은 0~255 히트맵을 이진화하는 기준이다. 평균 공 크기가 약 5픽셀이라 정답 가우시안을 σ²=10으로 만들었고, 그 가우시안에서 값이 128인 영역이 공 크기와 대략 대응한다는 점을 근거로 정했다. (4장)

### WASB와 비교

- **출력 구조:**
    - TrackNet Model II: 연속 3프레임 입력 → 마지막 프레임의 히트맵 1장 출력 (서론, 5장)
    - WASB (N=3): 연속 3프레임 입력 → 각 입력 프레임에 대응하는 히트맵 3장 출력 (MIMO 구조, 5.2절)
    - 두 방법 모두 입력 프레임 수는 설정값이고, 위는 실험에서 쓴 값이다.

- **좌표 계산:**
    - TrackNet: 히트맵 이진화 → Hough 원 검출 → 원의 중심 좌표 반환
    - WASB: 히트맵 이진화 → Blob 추출 → CoH(Center of Heatmap)로 좌표 계산. Blob 내부의 히트맵 값을 가중치로 사용하며, 히트맵 값의 합을 Confidence로 사용한다.
